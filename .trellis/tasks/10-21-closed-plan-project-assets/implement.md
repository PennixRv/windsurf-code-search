# 执行步骤与停止点

1. 记录版本、平台、工作流 provenance、模板 hash、自定义内容和现有任务基线；由根完成 Lifecycle CLI 核验。
2. 在本项目运行已修复的原生 dry-run，逐字确认 hash 清单未变；根审阅全部六个预览后才执行更新。
3. 使用原生 create-new 与已批准迁移更新资产。审查完整差异及每个候选，保留定制，按根已定来源机制运行 workflow verify。
4. 核验版本、规划 Skill/任务脚本/Hook、现有任务与自定义内容，运行差异检查和相关合同检查；发现缺口在同范围修复并复核。
5. 只提交本任务资产与证据，推送 main。满足 owner 验收后原生归档本任务；无独立 PR 分支时按真实 main/base main 事实使用原生 skip-branch-validation。推送最终归档提交并记录最终 SHA。

每步以前步成功为前提。失败保留现场及原生备份，不扩大覆盖。停止点：项目更新和原生工作流核验通过，候选全部有处置，资产与归档均已推送且工作树干净，根取得最终 SHA。全局部署、源任务归档及最终真实宿主验收仍由根执行，不将其误记为本地已完成。
